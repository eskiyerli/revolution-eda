# AGENTS.md

## Quick orientation
- `reveda.py` is the app entrypoint. It creates `revedaApp`, loads `.env`, resolves `REVEDA_PDK_PATH` / `REVEDA_PLUGIN_PATH`, sets up `reveda.log`, and then opens `revedaEditor/gui/revedaMain.py:MainWindow`.
- This is a monolithic PySide6 desktop app. The main editing surfaces are `schematic`, `symbol`, and `layout`; editor creation is centralized in `revedaEditor/gui/editorFactory.py` and view opening is routed through `revedaEditor/backend/libraryModelView.py`.
- Libraries are file-backed. Editors read/write human-readable JSON cell views; plugins and PDKs consume those files rather than a service API.

## Architecture that matters when changing code
- `revedaEditor/gui/` owns windows, menus, dialogs, and editor chrome; `revedaEditor/scenes/` owns interaction/state for each editor; `revedaEditor/common/` owns reusable graphics items (`shapes.py`, `layoutShapes.py`, `net.py`, `labels.py`).
- JSON I/O is the real contract: `revedaEditor/fileio/loadJSON.py` reconstructs scenes, while `schematicEncoder.py`, `symbolEncoder.py`, and `layoutEncoder.py` define persisted keys such as `sys/scn/scp/txt`, `rect/line/pin/label/attr`, and `Inst/Rect/Path/Via/Pin/Label/Polygon/Pcell`.
- Layout PCells are resolved dynamically: `loadJSON.py:createPcellInstance()` expects the cell JSON header `{"cellView": "pcell"}` and looks up the class in `pcells.pcells`.
- Standard view types (`schematic`, `layout`, `symbol`) are opened by `EditorFactory`; other view types fall through to plugins via `pluginsLoader.openCellView()` / `createCellView()`.

## PDK conventions
- A PDK is a Python package pointed to by `REVEDA_PDK_PATH`; `revedaEditor/backend/pdkLoader.py` imports submodules as `<pdk_name>.<module>`.
- Module-level PDK bindings must use `lazyPDKModule("name")` (a proxy that resolves on first access), never eager `x = importPDKModule("name")` — PDK packages import `revedaEditor` modules during their own `__init__`, so eager bindings can capture `None`/partially-initialized modules and crash on class-level attribute use. Reserve `importPDKModule()` for function-local calls. The proxy supports `__getattr__`/`__setattr__`/`bool`; use truthiness (`if fabproc`) rather than `is None` checks.
- Working PDKs expose the same module set as `defaultPDK/`: `callbacks.py`, `process.py`, `schLayers.py`, `symLayers.py`, `layoutLayers.py`, and `pcells.py` or `pcells/`.
- Layer definitions must use the dataclasses in `revedaEditor/backend/dataDefinitions.py`: `edLayer` for schematic/symbol, `layLayer` for layout. Example: `defaultPDK/schLayers.py` builds derived layers with `dataclasses.replace(...)`.
- Callback classes read instance labels and usually convert them with `quantiphy.Quantity`; see `ihp_pdk/callbacks.py` (`cap_cmim`, `baseInst`) and `gf180_pdk/callbacks.py`.
- PyLabels are executable conventions, not plain text: `revedaEditor/common/labels.py:createPyLabel()` looks up a callback class whose name matches `parentItem.cellName` and renders the returned value with `Quantity(...).render(prec=3)`.
- Layout-only PDK menu actions come from `config.json`; `ihp_pdk/config.json` adds `Check -> DRC with KLayout` by pointing at `klayoutDRC.klayoutDRCClick`.

## Plugin conventions
- Plugins are only loaded if `REVEDA_PLUGIN_PATH` is set. `pluginsLoader` scans that directory with `pkgutil.iter_modules()`, reads each package's `config.json` **before importing**, then imports compatible packages by folder name.
- `config.json` is used for menu wiring and version/capability negotiation, not discovery. Required runtime fields are effectively `menu_items[].location/menu/action/callback`; `apply` must match the actual Qt window class name (for example `schematicEditor`, `layoutEditor`, `symbolEditor`).
- Negotiation is Qt-free in `revedaEditor/backend/pluginApi.py` (`PLUGIN_API_VERSION`, `CORE_CAPABILITIES`, `checkPluginConfig`). Optional `config.json` fields: `plugin_api`, `min_app_version`/`max_app_version`, `provides`, `requires_core`, `plugin_version`. An incompatible plugin is skipped entirely (never imported); reasons land in `pluginsObj.incompatible`. `pluginsObj.provides(cap)`/`capabilityProvider(cap)`/`pluginVersion(name)` are the editor-facing queries — use `provides()` to gate native actions an active plugin replaces; commercial providers are inactive without a valid license.
- `pluginsLoader.checkForUpdates()` fetches the registry (`pluginApi.DEFAULT_REGISTRY_URL`) on a worker thread once per day (QSettings-throttled, `REVEDA_DISABLE_UPDATE_CHECK` opt-out), caches registry results, emits `updatesChanged`, and logs newer `plugin_version`s. `MainWindow` exposes top-level `Plugins -> Browse Plugins...` / `Updates (N)` actions and a QSettings-backed discovery banner dismissed for 90 days; `pluginsRegistry` highlights outdated installs and offers Restart Now/Later after successful installation. Commercial first installs resume the pending plugin download asynchronously after `revedaLicense` finishes — never block the GUI thread with `QThread.wait()`.
- If a plugin handles custom views, expose `viewTypes` plus `openCellView()` and/or `createCellView()` from the package root. `plugins/revedasim/__init__.py` is the canonical example (`viewTypes = ['revbench']`).
- Keep import side effects small: a failing plugin import is logged and the plugin is skipped.
- Injected menu actions default to mutating and are disabled in lock-contended editors. Set `menu_items[].read_only_safe` only for actions that cannot change the design; `pluginsLoader` registers injected actions with `editorWindow` so its lock sweep can enforce this.
- SDL Pro consumes the versioned `sdlAdapterV1` core capability. Core owns persistence, PCell construction/parameter application, connectivity, undo mutation, overlay lifecycle signals, and generic probe selection; the plugin owns incremental correspondence policy, flyline topology/presentation, and cross-probing coordination.

## Licensing architecture
- The licensing system has two layers:
  - `revedaLicense/` — proprietary module containing the real implementation (`licenseManager.py`). This is compiled to `.pyd`/`.so` for distribution and is **never** committed to the public repo (excluded via `.gitignore`).
  - `revedaEditor/backend/licenseManager.py` — open-source compatibility shim. It re-exports from `revedaLicense` when present, or provides stubs so the base app starts without it.
- Plugins import from `revedaEditor.backend.licenseManager`, never directly from `revedaLicense`.
- License validation uses Ed25519 signatures. The public key in `revedaLicense/licenseManager.py` is XOR-obfuscated to resist extraction from Nuitka binaries.
- Server-side tooling (`scripts/generate_license.py`, `scripts/obfuscate_key.py`) must never be committed to the public repo.
- Private keys (`*.pem`, `*.key`) are gitignored. Only `.env.example` is committed; `.env` itself is not.

## Connectivity architecture (single semantic model)
- `revedaEditor/connectivity/` is the ONLY connectivity implementation. Everything connectivity-related must go through it: GUI scenes, checks, netlisters, probes, RCX, aiTerminal design ops, and importers. Do not add parallel union-finds or pin-mapping code elsewhere.
- Schematic path: `analyzeItems` (live items) and `analyzeRecords`/`checkRecords` (decoded JSON arrays). `schematicScene.connectivity` is the cached engine result; `rebuildConnectivity()` forces a fresh build. `loadJSON.makeSymbolPinLocator` supplies symbol pin positions for the record path.
- Layout path: `connectivity/layout.py` holds the Qt-free geometric engine (`LayShape`, `LayVia`, `PcellBridge`, `buildConnectivity`, `assignNetNames`, `LayoutGeometryReader`). `adapters.fromLayoutItems` maps live items; `layoutScene.connectivity` exposes cached `NetGroup`s; `highlightNetAtPoint`/`clearNetHighlights` implement Highlight Net. `rcextraction/layoutGeometry.py` is a re-export shim — RCX consumes the shared engine.
- Cache discipline: scenes mark connectivity dirty on `changed`/`addItem`/`removeItem`. If you add a new item kind that carries connectivity (e.g. new pin type), extend `adapters.py` — never a scene-local scan.
- New persisted fields still need: encoder + `schemaValidation.py` coverage + tests in `revedaEditor/tests/`.

## Parameter model (CDF-lite)
- `revedaEditor/common/params.py` is the ONLY typed-parameter engine — Qt-free, so GUI, load path, diagnostics, and importers share it. Do not re-implement param validation elsewhere.
- Persistence: a reserved symbol attribute `paramDefs` (`nam="paramDefs"`, `def`=JSON list of `{name, type, default, min, max, choices, display, parse}`). Types: `float|int|string|boolean|choice`. `parse` allows quantiphy suffixes ("1k", "2u").
- Instance values stay in `sys.ld` (`@name: [value, visible]`); `schematicSymbol.paramDefs` exposes the parsed defs. `paramDef.default` overrides the NLP label default when the instance value is empty; `pPar("name")` in a default resolves against sibling label values on the instance (same convention as PyLabel's `parentItem.labels`).
- Authoring: symbol editor "Symbol Properties" dialog has a Parameters table (the `paramDefs` attr is hidden from the free-form attr grid). Instance edit uses typed widgets via `propertyDialogues.paramValueWidget` (also used by the place-with-form `placeInstanceDialog` in `createInstClick` → `scene.pendingInstanceParams`).
- Headless path: `connectivity.diagnostics.checkRecords` validates `sys.ld` values when the pin locator supplies `paramDefs` (`loadJSON.makeSymbolPinLocator` provides it). Importers emit `paramDefs` via `createSymbols._paramDefsAttribute`.
- aiTerminal: the plugin lives outside this repo; it must consume `paramDefs` from symbol attrs (via the locator or `params.paramDefsFromSymattrs`) and produce type-valid `ld` values — never bypass `params.py` validation.

## Net expressions & inherited connections (netSet)
- `revedaEditor/connectivity/netexpr.py` is the ONLY expression engine — Qt-free, shared by GUI, record checks, and all three netlisters via `netlisting/exprSupport.py`. Never evaluate `[@...]` strings elsewhere.
- Syntax: `[@name]` / `[@name:default]` on `nx` fields (`scn` wires, `scp` sheet pins, symbol `pin` records) and live items' `netExpr`. `netSet` (per-instance `{exprName: localNet}` overrides) persists as `nst` on `sys` records and as `schematicSymbol.netSet`.
- Evaluation happens once inside `connectivity.resolve`: sheet-level carriers (scn/scp) use the sheet binding; symbol-pin exprs merge their owning instance's `netSet` over the sheet binds (instance wins, unbound names propagate up). `!`-suffixed results behave like global pins; plain results assert a pin-tier (connect-by-name) name weaker than SET.
- Hierarchy: every distinct expr name inside a cell becomes an implicit subcircuit terminal (appended after `pinOrder` on the `.SUBCKT`/subckt header); at instantiation the instance line supplies netSet override → default → bare name, in sorted expr-name order. `exprSupport.terminalNetSet` = identity binds for collecting a subckt's internals; `exprDefsForSchematicView` reads a child view's defs from JSON without opening an editor.
- Diagnostics: `checkRecords(records, pinLocator=..., netSet=...)` reports `badNetExpr`/`exprDefaultConflict`, skips floating-pin warnings for expr-bearing pins, and accepts a binding context for hierarchical checks.
- GUI: net/pin property dialogs edit `netExpr`; the instance dialog edits `netSet` (`name=net,...`); Tools → "Show Resolved Net Names" toggles resolved-name display (`scene.toggleResolvedNames`, `schematicScene.showResolvedNames`).
- aiTerminal: write `nx`/`nst` fields directly in emitted records and call `checkRecords` with a `pinLocator` for validation — the same path GUI load uses.

## Schematic editing UX (Phase 4)
- **Find/replace:** `schematicScene.findItems(kind, pattern, prop)` returns `findHit` records (kind/name/detail/items/rect); `replaceHitName` renames instances (instanceName + `[@instName]` label), nets (every member segment, SET strength) and pins. `gui/findDialogue.py` hosts `findDialogue` (Ctrl+F, Edit menu) and `markerBrowserDialogue` — both non-modal, zoom-on-select.
- **Check markers persist:** `lastCheckViolations` round-trips through optional `mrk` records (`{type:"mrk", rule, sev, msg, rects}`) appended after items in `saveSchematic` and rebuilt by `_restoreMarkers` on `loadDesign`. `viewErrorsAction` opens the browser.
- **Bus ripper:** starting a plain wire on a `name<lo:hi>`-named net or pin sets `_wirePendingName = name<i>` for the whole chain (`_busRipIndex` is a one-shot index override; otherwise a prompt, single-member pins auto-rip). Only the drawn chain's own merge products get the member name — pierced bus halves keep the trunk name.
- **Clipboard (single copy model):** there is only one copy path — `c`/`Ctrl+C` (`copyAction` → `editorWindow.copyClick`) serializes the selection to the system clipboard via `editorScene.copySelectionToClipboard`, then `beginClipboardPaste` instantiates the fragment as a floating group that tracks the cursor (`copyItem` mode, `_copyAnchor` = snapped bbox top-left) until left-click commits via `_commitCopyGroup`; `Ctrl+V` (`pasteAction` → `pasteClick`) arms the same placement. Both route through `editorWindow._sceneUnderMouse()` so the copy lands in whichever editor's view the cursor is over. `editorScene._armedCopyScene` registers the armed scene app-wide: entering a *different* scene's view on `mouseMoveEvent` migrates the floating group via `beginClipboardPaste` (guarded by selectItem mode, no buttons held, `_clipboardAcceptable` type gate) so the copy keeps tracking the cursor and click-commits there; a stray click in a busy scene falls back to immediate `pasteClipboard` at the click point; ESC in any view calls `cancelArmedCopy()` which undoes the armed add-shapes command so the uncommitted copies leave no trace. The contract is per-scene class attrs `_CLIPBOARD_ENCODER`/`_CLIPBOARD_FACTORY`/`_CLIPBOARD_TYPES`/`_CLIPBOARD_SHAPES` + `_fixClipboardShapes` hook (fresh `I<n>` names); fragments that fail the `type` gate (e.g. schematic records into a layout scene) are rejected. `pasteClipboard(at)` is the immediate-commit headless variant. `applyBindkeys` accumulates all keyseqs mapped to one action via `setShortcuts`, so `C` and `Ctrl+C` coexist on `copyAction`. **Copy options (Virtuoso-style):** `scene.copyOptions` (`ddef.copyOptions`: `rows`/`columns`/`xOffset`/`yOffset` scene-unit pitch) drives `_clipboardShapesArray()` — shared by `beginClipboardPaste` and `pasteClipboard` — which instantiates the fragment `rows×columns` times offset by `(col·dx, row·dy)`; a zero pitch falls back to the fragment's bbox size. `_fixClipboardShapes` runs once over the whole array so `I<n>` names stay unique. While `copyItem` is armed, F3 (`editorView.keyPressEvent`, same key as draw-mode snap cycling) toggles `editorWindow.toggleCopyOptionsDialogue` → `pdlg.copyOptionsDialogue` (modeless, Apply/Ok/Cancel); Apply/Ok writes `copyOptions` and calls `scene.rearmClipboardPaste()` to rebuild the ghost live (cancel-undo + re-arm). The whole array is one `addShapesUndo`: single undo, single ESC-cancel.
- **Snap modes:** `cycleWireDrawMode` (schematic, F3) and `cyclePathMode` (layout, F3 during drawPath) are the unified in-draw snap-mode control.
- **Edit-in-place (spike):** `descendInPlace` ghosts a child cellview inside the parent scene — `QGraphicsItemGroup` with `setHandlesChildEvents(False)`, instance transform applied to the finished group (addToGroup preserves apparent position, so transform must come last). Ghost children are marked `_eipChild` (ancestor-aware check) and filtered out of connectivity, snap targets, checks, expr collection, and save. `setEipEditable(True)` makes them selectable for property edits; `saveInPlaceEdits` encodes children and back-transforms `st`/`end`/`loc`/`br` through the inverse instance transform into the child file. `ascendInPlace` removes groups. Known limits: no geometry-move proxy, no undo bridging for ghost edits.

## Layout editing UX (Phase 5)
- **Instance arrays (mosaics):** `layoutInstance.setArray(rows, cols, rowPitch, colPitch)` (pitches in scene dbu). `Inst`/`Pcell` records gain `rows`/`cols`/`rpt`/`cpt` only when arrayed — 1x1 records are unchanged. `_shapes` always holds element (0,0); `_ensureArray()` materializes the other elements as clones (encoder→`layoutItems` round-trip) into `_arrayShapes`/`arrayShapes` once the item is in a scene. GDS export emits a native `gdstk.Reference` repetition (`columns`/`rows`/`spacing` — read them via `ref.repetition` in gdstk 1.x).
- **Boolean/size ops:** `layoutBoolean.booleanLayerItems(items, op, amount)` returns `(produced, consumed)`; `layoutScene.booleanSelectedItems` pushes them through `addDeleteShapesUndo` (undoable). `or`/`xor` fold per-layer groups; `and` intersects sequentially (gdstk `boolean(operand, [], 'and')` returns empty — fold pairwise); `not` subtracts every *other* layer's union from each layer group (A-NOT-B); `grow`/`shrink` use `gdstk.offset` per shape (wrap operands as `[points]` — a bare point list is parsed as polygon-list). Hole results arrive as keyhole polygons — `layoutPolygon` handles them.
- **Multipart items:** `layoutMultipart` subclasses (`layoutGuardRing`, `layoutShieldedPath`, `layoutBusRoute`, registered in `MULTIPART_KINDS`) are editable composites: children regenerate from a plain-JSON `params` dict via `_build()`; layers/vias persist by *name* and resolve through `importPDKModule` at build time (never store layLayer objects in params). Persisted as `{"type": "Multipart", "kind", "params", loc/top/ang/fl}`; children are NOT serialized. Two-click draw: `drawLayoutMultipart` anchors pos on click 1 and calls `updateDraftGeometry` on move/click 2. Export emits children with `frameItem=item.parentItem()` so they land in the parent cell's frame.
- **Hierarchy restructuring:** `layoutFlatten.flattenInstance(instance)` bakes descendants to scene-coord leaf items (rotations, flips, mosaic elements all composed through `mapToScene`; also explodes `layoutMultipart`). `flattenSelection` (Hierarchy menu) is undoable. `makeCellFromSelection(lib, cell)` writes `lib/cell/layout.json` with contents shifted by -selectionBounds.bottomLeft and swaps in an undoable `layoutInstance`.
- **Item grouping:** `layoutScene.groupSelectedItems`/`ungroupSelectedItems` (Ctrl+G / Ctrl+Shift+G, also in the context menu) wrap selected top-level items in a `layoutGroup` — a persistent parent item whose members keep scene coords as group-local coords and carry only `ItemStacksBehindParent` while grouped, so the group selects/moves/copies/deletes as one unit (nested groups allowed). Persists as `{"type": "Group", "items": [...], loc/top/ang/fl}` — member records are group-local, the group transform follows the instance convention; `_applySceneTransform` folds group transforms back into member pos/ang/fl on release (path/ruler use negated-rotation `angle`, labels use additive extra rotation). Undo via `undoStack.undoGroupShapes` (attach/detach — members stay in scene, only the parent changes). Connectivity (`fromLayoutItems` and `LayoutGeometryReader`) and GDS export treat groups transparently — grouped pins/labels still anchor nets; flatten recurses through them.
- **Stream options:** `gdsExporter` accepts `layerMap` `{(gdsLayer,datatype):(gdsLayer,datatype)}` (applied via `_emitLayer` at every emission incl. via cuts/enclosures), `cellNameMap` `{name_or_lib_cell_view: gdsName}` (`_mapCellName`), `flattenDepth` — `None` keeps hierarchy, `0` flattens all, `N` keeps refs only at depth ≤ N (flattened children emit into the parent cell via the caller's `frameItem`; `mapToItem` composes the full Qt chain). Dialog: `layoutExportDialogue` parse helpers `layerMap()`/`cellNameMap()`/`flattenDepth()`.
- **Import merge mode:** `gdsImporter.mergeMode=True` reuses existing cells/views (`_cellItemFor`/`_viewItemFor` — note `createCellviewItem` truncates, so merge wraps existing layout.json in a bare `viewItem`) and appends new shape records after existing ones; `_instanceCounters` are seeded from existing `Inst.ic` values so merged instance names stay unique. `revedaMain.importGDSClick` skips the library `rmtree` when merging.
- **Rulers:** endpoint label shows `length` in layout units (`_lengthToLayoutUnits`; Y follows the scene's Y-down convention like every other layout coordinate). F3 during drawRuler opens `rulerOptionsDialogue` (`scene.rulerMode` Manhattan/Diagonal/Any-Angle + `scene.rulerSnapToEdge`); the ruler's boundingRect margin is cached and only refreshed from `paint()` when the view scale drifts >10%, and fit/print/export all go through `scene._fitBoundsRect()` so the zoom-dependent label margin can't feed back into zoom. `deleteSelectedRulers` (Ctrl+K) removes only selected/grouped rulers via undo; `deleteAllRulers` (Shift+K) unchanged.
- **Hierarchy-aware net highlight:** `adapters.fromLayoutItems` expands container items (anything exposing `.shapes` — `layoutInstance`/`layoutPcell`/`layoutMultipart`, incl. `arrayShapes` clones and nested instances) so internal metal/pins/vias join `buildConnectivity` as ordinary shapes resolved in scene coordinates. Highlight-net therefore reaches through hierarchy (e.g. metal inside a psub tap) and clicks on internal shapes resolve the top net via `_connectivityItemGroup`/`_layoutGroupAtPoint`. Internal pins/labels are deliberately NOT name anchors — nets are named by top-level pins/labels only (instance terminal names must not rename or conflict). RCX is unaffected: it reads records via `LayoutGeometryReader`, not `fromLayoutItems`. `rebuildConnectivity` prunes highlight overlays whose item left every net.
- **Dead modes removed:** `drawArc`/`drawCircle`/`drawLine` were removed from `layoutModes` — layout has no arc/circle items and `layoutLine` is only the internal cut guide. Symbol editor keeps its real line/arc/circle modes.

## Schematic<->layout correspondence (Phase 6)
- **The `sdl` contract:** `Inst`/`Pcell` records carry an optional `sdl` field (`{"lib","cell","view","inst","labels"}`) identifying the *source schematic cellview* plus the instance inside it; live items mirror it as `layoutInstance._sdlSource`. `backend/correspondence.py` is the Qt-free engine: `makeSdlSource`/`sdlInstName`/`sdlSourceKey`/`sdlLabels` normalize access (legacy in-memory dicts used `schematicLib`/`schematicCell`/`schematicInstance` — they have no source key and only match by name). `schematicInstances` extracts `{name: sys-record}`; `pcellParamsFor` maps schematic labels → pcall kwargs via the PDK's `pcellParameterMap.json`.
- **SDL split (free core + SDL Pro plugin):** the free editor's `Tools → Load from Schematic…` (`sdlLoadClick`) is destructive by design: it picks a schematic, confirms, then `scene.clear()` + `itemsRefSet.clear()` + `undoStack.clear()` (stale undo commands would reference deleted items) before `loadSchematicInstances` places instances without `sdl` stamps. Invoked directly, `loadSchematicInstances` still confirms and bulk-deletes existing instances via one `deleteListUndoStack` command. `updateFromSchematic(schematicTuple)` remains the incremental engine — `correspondenceDiff` → one undo macro (`to_add`/`to_remove`/`to_update`/`adopted`; foreign-source and unmatched instances untouched) — consumed by SDL Pro through the versioned `sdlAdapterV1` core capability. The scene's adapter surface: `resolveLayoutView`, `createLayoutInstanceFromRecord`, `stampSdlSource`, `applySchematicParameters`, `removeLayoutItemsUndo`, `layoutInstanceDescriptors`, `topLevelLayoutInstances`/`topLevelLayoutPins`, `descendantLayoutPins`, `pcellPinMap`, `layoutPinInInstance`, `connectivityGroupForItem`, `probeTargets`, `addOverlayItem`/`removeOverlayItem` (bypass connectivity dirtying), `sdlMutationAllowed` (read-only gate), and `connectivityInvalidated`/`connectivityRebuilt` signals. The native `Load` action is suppressed only while `pluginsObj.provides("sdl")` is true — inactive/unlicensed providers don't suppress it.
- **Flylines (rat's nest):** `corr.flylineEndpoints(records, pinLocator)` resolves `{net: [(instName,pinName)]}` through the shared connectivity engine on *records* — `("",pinName)` marks sheet-level pins. `layoutScene.rebuildFlylines` maps endpoints to layout pin scene positions (`_layoutPinForEndpoint`/`_layoutPinInInstance` resolve via sdl name → instanceName, `_childLayoutPins` walks nested internals/arrays; cells whose symbol pins differ from layout pin names — e.g. rsil `P`/`M` vs `PLUS`/`MINUS` — declare the mapping in `pcellParameterMap.json` `pinMappings`, forward for flylines/schematic→layout probing and inverted for layout→schematic probing), caches `{net: [pinItems]}` in `_flylinePins`, and draws `layoutFlightLine` dashes between unrouted connectivity islands. Not a `layoutShape` — never persisted, never selected, pure overlay. Sync auto-rebuilds; `_inferFlylineSource` recovers the source from any sdl-stamped instance. **Live tracking:** each `layoutFlightLine` stores its endpoint pins — `markConnectivityDirty` → `_updateFlylineGeometry` re-anchors lines on every change (lines follow drags; dead pins drop), while `rebuildConnectivity` → `_syncFlylines` re-evaluates island topology from the cached pins (merged islands drop, splits gain). `mouseReleaseEvent` and `undoStack.indexChanged` force the rebuild after moves/undo. `_syncingFlylines` guards re-entrancy since flyline add/remove emits `changed`.
- **Cross-probing:** the menu actions moved to the SDL Pro plugin; core keeps the primitives — `layoutScene.probeSchematic`/`probeTargets` (instance sdl names + `_endpointsForGroup` pin endpoints) and `schematicScene.probeLayout`/`probeTargets` (symbol names + `netEndpointsForItem` group ports) look the counterpart editor up in `appMainW.openViews[viewNameTuple]` and call `selectProbeTargets` — instances get selected+zoomed, net endpoints resolve through connectivity so probing is name-agnostic. Counterpart editor must be open (messageLine explains otherwise).

## Platform hardening (Phase 7)
- **Cellview lock files:** `backend/cellviewState.py` is the Qt-free contract — `lockPathFor(view.json)` = `view.json.lock` (name-appended so the save writers' `with_suffix(".tmp")` staging files never collide), `acquireLock` returns `"held"`/`"contended"` (`{pid,user,host,time}` payload, atomic write), `processAlive` is POSIX `os.kill(pid,0)` + Windows `OpenProcess`. Missing/malformed/dead-pid locks are stale and taken over. `editorWindow._initSessionState` acquires at construction; contention → `scene.readOnly`, checked+disabled `readOnlyCellAction`, disabled save/check actions. `closeEvent` calls `releaseLock` (ownership-checked) — and the subclass close auto-saves are gated on `_lockHeld` so a read-only window can never clobber a foreign file.
- **Autosave + crash recovery:** `autosavePathFor(view.json)` = `view.json.autosave`. `editorWindow._autosaveTimer` (interval `autosaveIntervalSec`, gated on `autosaveEnabled` — both reveda.conf keys, default 300s/True) calls `autosaveCellview`: skips clean scenes and unchanged undo indexes, writes via `_saveCellviewTo(path)` which dispatches the scene's save method with `markClean=False` (the scene saves parameterize `undoStack.clear()` — autosave must preserve undo history). `loadX` entry points call `_resolveLoadPath`: a newer *parseable* autosave prompts a restore dialog (Yes loads it, No deletes it); corrupt autosaves are removed without prompting (`isAutosaveUsable`). Real saves call `_clearAutosave`; `closeEvent` removes it when we hold the lock.
- **Bindkeys:** `resources/bindkeys.json` ships defaults as `{section: {keySeq: actionAttrName}}` — `"*"` plus per-viewType sections (`schematic`/`layout`/`symbol`) since the same key means different actions per editor (`W` = net/path/line). `runPath/bindkeys.json` merges over it (`backend/bindkeys.loadBindkeyMap` → `appMainW.bindkeyMap`); `editorWindow._applyConfiguredBindkeys` → `applyBindkeys` resolves attribute names to QActions after `_createShortcuts`, so config wins over hardcoded defaults and unknown names/empty sequences are logged and skipped.
- **Session save/restore:** `reveda.conf` gains `openCellviews`: `[{library, cell, view, geometry:[x,y,w,h], viewRect:[x,y,w,h]}]` written by `MainWindow._sessionSnapshot` (windows without `centralW.view` are skipped) from both `saveAppState` and `ProjectManager.save_current_state`. Restore runs in `ProjectManager._apply_state` via `MainWindow._restoreSessionViews` — resolves lib/cell/view items through `libm.get*Item`, dedupes via `openViews`, applies window geometry and `view.fitInView(viewRect)` zoom; missing cellviews are skipped per-entry. `loadAppState` also schedules `_restorePendingSession` via `QTimer.singleShot(0)` for the non-project path (`appMainW` isn't assigned yet during `MainWindow.__init__`).

## Codebase-specific patterns to preserve
- Scene edits are expected to be undoable. Reuse commands in `revedaEditor/backend/undoStack.py` instead of mutating `QGraphicsScene` state ad hoc.
- Saved geometry is scene-origin-relative in many encoders (`*_Encoder._subtract_point(...)`); preserve that convention when adding new JSON fields.
- Symbol instances tolerate missing libraries by creating a draft placeholder (`loadJSON.py:createDraftSymbol()`); avoid turning unresolved references into hard crashes.
- Many UI extensions are convention-based: menus are injected by config, PDK modules are imported by fixed filenames, and callbacks are found by symbol/cell names. Renames across those boundaries break runtime discovery.
- If you need representative examples, use `defaultPDK/` for minimal built-in behavior, and `plugins/aiTerminal`, `plugins/revedasim`, and `plugins/revedaPlot` for plugin patterns. External PDKs (`ihp_pdk/`, `gf180_pdk/`) are in separate repos but follow the same conventions.
- Use camelCase convention in class, method and variable names.
- Make sure to prioritize implementation efficiency in the code as we are using Python.
