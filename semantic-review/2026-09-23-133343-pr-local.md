# Unify typed placement and Instance Properties around label carriers

The change now consistently binds typed parameters only to persistent NLP label carriers, preserves per-instance PyLabel visibility controls, and keeps `display=false` siblings available to `pPar()` default resolution without rendering them. Schematic placement has regression coverage for its live preview callback, and hierarchical symbol/layout loaders reject unsupported schema versions before constructing child records. Layout PCell placement also retains the first accepted parameter and mosaic options for subsequent clicks in the same placement command.

**Verdict**: PASS

## High-level view

The placement and Instance Properties flows share the same carrier model while preserving their distinct presentation needs. Typed definitions provide widget and validation metadata; instance values continue to round-trip through `sys.ld`; fixed normal labels remain read-only; and callback-derived PyLabels remain value-read-only while retaining an editable visibility setting.

Schema compatibility is enforced for both top-level and hierarchical load paths, preventing unsupported future child formats from being partially interpreted. Accepted PCell placement options are stored in scene state so repeated placement behaves consistently with the active-command model and F3 editing.
